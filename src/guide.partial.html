Explore deployment options

Once an offering fits, this is what you still choose inside it. Figures are maximums that depend on hardware, size and region — read them as ceilings, not defaults, and confirm against the linked documentation before you commit to a configuration.

VM family and size

Consider when the workload needs the operating system, a specific SQL build, or an instance feature the managed services do not expose.

Deployment
Marketplace SQL image, or install onto your own VM
Compute
Memory optimized for most production work. Ebdsv5 is the documented starting point; Mbdsv3 and M-series for the largest workloads
Storage
Storage optimized L-series for I/O-heavy staging on ephemeral local NVMe
Licensing
Constrained vCore sizes cut the billable SQL core count while keeping memory and I/O
Configuration details and limits
Minimum
4 or more vCores for production; E4ds_v5 is named as a minimum recommended size
Memory
8:1 memory-to-vCore is the recommended starting ratio. D-series runs 4:1; Mds_v3 reaches 16:1 and above for data warehousing
Constrained
Two models: preset reductions on selected families, and configurable constrained cores across a broader set. Both keep the parent VM's memory and I/O, and you still pay parent compute and Windows licensing
Local NVMe
The L-series NVMe is ephemeral: data held there is lost when the VM is deallocated, so it suits tempdb and staging rather than data files

Storage architecture

Consider this before VM size — disk layout and caching decide SQL throughput on IaaS more often than core count does.

Disk types
Premium SSD v2 or Premium SSD for production; Ultra Disk where the log needs submillisecond latency
Layout
Separate volumes for data, log and tempdb
tempdb
On the ephemeral temp disk for most workloads; on shared storage for cluster instances
Caching
Read-only on data, none on log, on Premium SSD
Configuration details and limits
Per disk
Ultra Disk up to 400,000 IOPS and 10,000 MB/s · Premium SSD v2 up to 80,000 IOPS and 2,000 MB/s · Premium SSD up to 20,000 IOPS and 900 MB/s
Ceiling
The VM series caps uncached IOPS and throughput independently, so the effective limit is the lower of the two. Above roughly 160,000 IOPS the guidance is Premium SSD v2 or Ultra Disk
Host caching
Read-only on data and none on log applies to Premium SSD. Premium SSD v2 and Ultra Disk do not support host caching at all, and nor do disks of 4 TiB and larger
Restrictions
Ultra Disk is locally redundant only, is unavailable in some regions and VM sizes, and cannot be used with availability setsRegional Deploying a SQL VM on Premium SSD v2 through the portal is in preview and limited to Ebdsv5 and Ebsv5Preview

HA/DR topology

Consider how much availability you want to own. Azure supplies the infrastructure; you design, configure and operate the SQL-level topology.

Database
Always On availability groups, with replicas across zones or regions
Instance
Failover cluster instance over shared storage
Placement
Availability zones, or an availability set
Recovery
Secondary replicas in another region, backup to blob storage, or Azure Site Recovery
Configuration details and limits
Shared storage
Five documented options for a cluster instance: Azure shared disks, Storage Spaces Direct, Premium file shares, partner replication, and remote iSCSI over ExpressRoute
Prerequisites
Availability groups and cluster instances both need a Windows failover cluster and an Active Directory domain. Cross-region replicas need network connectivity between the virtual networks
Licensing
A passive replica kept for high availability or disaster recovery can use the free HA/DR licence type
Reference
Business continuity overview
Additional options
Operating system
Windows Server or Linux. Linux images carry SQL Server 2017 and later
Versions
Marketplace images for SQL Server 2025, 2022, 2019, 2017 and 2016. Images deploy at RTM and are not patched over time
Editions
Enterprise, Standard, Web, Developer, Express and Evaluation. Licence-model changes apply to Standard and Enterprise only
Licensing
Pay-as-you-go, Azure Hybrid Benefit, or the free HA/DR type. Hybrid Benefit needs core licences with Software Assurance or subscription licences; switching needs no downtime and no restart
Management
The SQL IaaS Agent extension adds automated backup, automated patching, Key Vault integration, best-practice assessment and Defender for Cloud, at no chargeRegional Supported in a limited set of regions. Registration alone installs no agent — each feature you enable pulls in what it needs
Networking
The VM sits in your virtual network, secured with network security groups
Free offer
No managed free tier. Developer edition carries a free SQL licence and Express is free within its own limits — in both cases you still pay for VM compute and storage

DTU purchasing model — a supported alternative to vCore

Bundles compute, storage and I/O into one unit rather than letting you size them separately. Suited to customers who want a preconfigured bundle and a predictable monthly figure. Available for single databases and, as eDTU, for elastic pools. You can convert between DTU and vCore.

Basic
5 DTU · up to 2 GB
Standard
S0 to S12, 10 to 3,000 DTU · up to 250 GB on S0 to S2, up to 1 TB above
Premium
P1 to P15, 125 to 4,000 DTU · up to 1 TB on P1 to P6, up to 4 TB on P11 to P15Regional A few regions cap P11 to P15 at 1 TB
Note
Azure Hybrid Benefit does not apply to this model, and Basic through S2 provide less than a full vCore of compute
Additional options
Redundancy
Zone redundancy where the region and hardware support it, plus active geo-replication and failover groups
Networking
A public endpoint by default; private access through Private Link, with firewall and network access controls
Licensing
Azure Hybrid Benefit applies to provisioned vCore only. It does not apply to serverless, to the DTU model, or to new Hyperscale databases. With Software Assurance, one Enterprise core covers 4 General Purpose vCores or 1 Business Critical vCore; one Standard core covers 1 General Purpose vCore
Backup
Locally, zone or geo-redundant backup storage, 1 to 35 days of point-in-time retention with 7 by default, and long-term retention up to 10 years
Security
Transparent data encryption and Microsoft Defender for SQL
Free offer
100,000 vCore-seconds of General Purpose serverless compute, 32 GB of data and 32 GB of backup each month for the lifetime of the subscription, across up to 10 databases When the monthly allowance runs out you choose in advance whether the database pauses until the next month or continues at standard rates
